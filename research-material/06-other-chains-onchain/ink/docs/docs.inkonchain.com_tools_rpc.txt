## Subblocks

Subblocks (formerly Flashblocks) are partial blocks that the Ink sequencer streams while it is still building the full block, roughly every 200 ms. They let your application see a transaction’s outcome as a pre-confirmation, before the block is sealed.

The subblocks endpoints are WebSocket streams. Each message is a JSON payload with a payload_id , an index , and a diff of the block being built. The first message for a block ( index 0) also includes a base containing the block header fields.

## Ink Mainnet

* Websocket: wss://subblocks.inkonchain.com/ws

## Ink Sepolia

* Websocket: wss://subblocks-sepolia.inkonchain.com/ws

⚠️
A pre-confirmation carries the sequencer’s trust assumption, not the protocol’s. It can be revoked under the same conditions that allow the sequencer to reorg unsafe blocks. In streamed payloads, state_root and block_hash are always zero, so do not treat them as authoritative.

To read pre-confirmed state over JSON-RPC (for example with eth_call or eth_getBalance and the pending block tag), use an RPC provider that supports subblocks. See the Optimism subblocks documentation for more detail.
